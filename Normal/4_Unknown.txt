CARD TYPE: NORMAL UNKNOWN

SECTION PURPOSE

This is the primary image-recognition card type for the NORMAL engine.

-----------------------------------------------------

TRIGGER CONDITION

NORMAL UNKNOWN exists only when BOTH are populated:
- Image
- Question

If either is missing:
- this is not NORMAL UNKNOWN

If any non-UNKNOWN trigger field or front-driving prompt family is also populated:
- the note is structurally invalid

Exception:
- Differentials is allowed on a NORMAL UNKNOWN note only as back-side mimic/confusion support.
- Differential_Q must remain blank unless the user explicitly requested a separate NORMAL DIFFERENTIAL DRILL.

-----------------------------------------------------

WHEN TO USE NORMAL UNKNOWN

Use NORMAL UNKNOWN when the learner must identify from the image:
- a structure
- a landmark
- a spatial relationship
- an expected normal appearance
- a normal physiologic appearance
- a normal variant
- the key normal feature preventing overcall

This is NOT a disease-diagnosis card.

Use NORMAL UNKNOWN only when the image truly supports recognition of the target or of a genuine high-yield orientation anchor.

If the named target is usually mainly topographically inferred rather than directly seen:
- do not force a pure identification UNKNOWN card
- convert it to a localization-focused card, usually NORMAL HIGH-YIELD
- or ask instead for the visible anchor landmark if that is the real image-grounded task

-----------------------------------------------------

FIELD MATRIX

Required:
- Clinical_Context
- Image
- Question

Conditionally allowed:
- Image_Annotated
- Entity_Label
- Differentials
- Imaging_Differentiation
- Original_Caption

Forbidden:
- Most_Likely_Diagnosis

- Mechanism_Q
- Mechanism

- Boards_Trap

- High_Yield_A

- Radiopaedia_Case_Context
- Radiopaedia_Case_Summary
- Radiopaedia_Case_Differential

-----------------------------------------------------

QUESTION DESIGN RULE

Question should ask for one image-based recognition task only.

Good question goals:
- identify the labeled structure
- identify the landmark anchoring the review
- identify the normal relationship shown
- identify the expected normal appearance
- decide whether the finding is normal, a variant, or abnormal
- identify the feature that keeps the appearance from being overcalled

Question must NOT:
- name the answer
- embed discriminator prose that solves the card
- ask for a broad pathology differential
- become a multi-step essay prompt
- ask the learner to name a small nucleus, tract, or subdivision as though it were crisply visible when the real task is topographic inference
- contain workflow or metadata wording such as "this batch", "source review", "extraction", "prompt", or "what was included"

If a draft question has process/meta shape, convert it into a direct image-recognition, localization, normal-appearance, overcall-prevention, or review-path question. If no useful target remains, omit the card.

-----------------------------------------------------

FRONT-SIDE BLINDING

Front should contain only the fields required by the shared template for this card type:
- Clinical_Context
- Image
- Question

Clinical_Context should remain:
- short
- neutral
- non-diagnostic
- unique at the note level

Do not leak the answer through front wording, captions, or label text.

-----------------------------------------------------

BACK-SIDE RULE

Entity_Label should hold the target answer or core concept label.

Rendered back priority:
1) Target structure, relationship, normal variant, or localization answer
2) Key normal imaging features
3) Mimics / overcalls / nearby confusions, when useful
4) Key differentiators or localization rule
5) Source caption/readout, verbatim if available
6) How to read the image(s)
7) Typical source-supported normal appearance by modality
8) Clinically useful reporting/localization consequence, when relevant
9) Complete image reference name(s)

Map this into existing fields:
- Entity_Label holds the target answer.
- Differentials holds realistic mimics, normal variants, pseudolesions, or nearby confusions.
- Imaging_Differentiation starts with "Key differentiators:" or "How to localize:" when that is the main teaching move.
- Original_Caption or Image_Annotated stackCap contains verbatim caption text only.
- Complete image reference names must appear in a separate back-side line/block, never by modifying verbatim caption text.

Imaging_Differentiation may briefly explain:
- why it is normal
- what makes the relationship normal
- what feature marks it as a variant rather than pathology
- whether the target is directly visible, variably visible, or mainly inferred
- which visible landmarks make the localization safe
- the concise practical localization rule when that materially improves the card
- complete image reference name(s), one per image, in display order, unless already included as a separate image-reference block in Image_Annotated

Do not turn the back into a long narrative.
Do not populate forbidden fields to add extra teaching.

-----------------------------------------------------

LANDMARK RULE

NORMAL UNKNOWN is an appropriate home for exam-approach content only when the approach concept is image-grounded.

Examples:
- "Identify the first landmark that should anchor review of this study."
- "What normal relationship is being confirmed on this phase or sequence?"

If the teaching point is a general review checklist rather than image recognition:
- use NORMAL HIGH-YIELD instead

-----------------------------------------------------

UNKNOWN SAFETY CHECK

Before export, confirm:
- Image is populated
- Question is populated
- Question is the only front-driving prompt family
- no non-UNKNOWN trigger fields are populated
- no forbidden fields are populated
- Differentials, if populated, appears only as back-side support and has no Differential_Q
- Image_Annotated is blank unless Image is populated
- Original_Caption is blank unless Image is populated
- the question does not leak the answer
- the image truly supports recognition
- summary is populated only when required

If the workflow explicitly states that no pictures are being provided for the run:
- generate zero NORMAL UNKNOWN cards
- do not fabricate image-driven prompts
- do not attempt to convert text-only content into fake UNKNOWN cards
